## 文档规范

### 1. 版本标记头

每个文档必须在开头添加版本标记头：

```markdown
# 文档标题

---

**文档版本**: v1.0  
**最后更新**: YYYY-MM-DD  
**适用版本**: v3.0.0+  
**状态**: ✅ 已同步代码 / ⚠️ 待更新 / ❌ 过时

---
```

### 2. 测试统计数据

涉及测试统计的文档必须保持数据一致：

| 项目 | 数值 | 说明 |
|------|------|------|
| 后端测试 | 467 | pytest测试用例总数 |
| 后端测试文件 | 43 | pytest测试文件数 |
| 前端测试 | 130 | Vitest测试用例总数 |
| 前端测试文件 | 16 | Vitest测试文件数 |

### 3. 链接规范

- 内部链接使用相对路径：`[文档](./API_CHANGELOG.md)`
- 外部链接需要标注：`[外部资源](https://...) ↗`
- 避免使用锚点链接，如需要请确保目标存在


2. **测试统计一致性**: 验证测试数据是否匹配期望值

## 更新流程

### 修改文档时

1. **更新版本标记**: 递增文档版本号，更新最后更新时间
2. **同步相关文档**: 检查并更新引用了相同信息的其他文档
3. **运行检查脚本**: 确保没有引入链接错误或数据不一致

### 发布新版本时

1. **统一更新**: 所有文档的`适用版本`更新为新版本
2. **API变更**: 更新`API_CHANGELOG.md`记录接口变化
3. **弃用说明**: 如有弃用功能，更新`DEPRECATIONS.md`

## 常见问题

### Q: 如何添加新文档？

1. 在合适的位置创建文件（`docs/` 或 `.agents/`）
2. 添加版本标记头
3. 更新相关索引（如 `README.md` 文档地图、`CLAUDE.md` 文档索引）
4. 运行检查脚本验证

### Q: 发现文档不一致怎么办？

1. 以最新的代码为准
2. 更新相关文档保持一致
3. 如果无法确定，查看 `git log` 找到最近的修改

### Q: 文档应该放在哪里？

| 位置 | 用途 |
|------|------|
| `docs/` | 项目级文档（架构、需求、API变更等） |
| `.agents/` | 开发规范、操作指南、检查清单 |
| `backend/docs/` | 后端专属文档 |
| `frontend-v3/docs/` | 前端专属文档 |
| `tests/` | 测试相关文档 |
