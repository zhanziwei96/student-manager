# 多班级并行上课功能设计文档

## 1. 概述

### 1.1 背景
当前系统限制教师同一时间只能管理一个课堂。实际业务场景中（如上午1-2节，多个班级同时在机房上课），教师需要同时监控多个班级的签到情况。

### 1.2 目标
支持教师同时开启和管理多个班级课堂，每个班级有独立的签到状态和学生列表。

### 1.3 设计决策汇总

| 决策项 | 选择 | 说明 |
|--------|------|------|
| 班级数量限制 | 软限制5个 | 超出时弹窗提醒，但仍可继续 |
| 移动端交互 | 下拉选择器 | 节省空间，切换效率高 |
| 数据刷新策略 | 智能按需刷新 | 当前班级5秒轮询，其他暂停 |
| 结束课堂确认 | 统一确认弹窗 | 所有结束操作都需确认 |
| 网络错误处理 | 即时提示+手动重试 | 顶部红色横幅+重试按钮 |
| 空班级处理 | 前置检查阻止 | 开启前检查，无学生则阻止 |

### 4.2 数据刷新策略

```typescript
// useClassSessions 优化
export function useClassSessions() {
  return useQuery({
    queryKey: ['classSessions'],
    queryFn: classSessionApi.getCurrent,
    refetchInterval: (data) => {
      // 智能刷新：有活跃课堂时5秒刷新，否则30秒
      return data && data.length > 0 ? 5000 : 30000
    },
    staleTime: 3000,
  })
}

// 当前选中班级的签到数据
export function useTodayCheckins(className: Ref<string>) {
  return useQuery({
    queryKey: ['today-checkins', className],
    queryFn: () => checkinApi.getTodayCheckins(unref(className)),
    refetchInterval: 5000,  // 当前班级5秒刷新
    enabled: !!unref(className),
  })
}
```

## 6. 错误处理

### 6.1 网络错误

```typescript
// 在 queryClient 配置中
defaultOptions: {
  queries: {
    retry: 0,  // 不重试，立即显示错误
    onError: (error) => {
      showNetworkErrorBanner(error)
    }
  }
}

// 错误提示组件
<NetworkErrorBanner 
  v-if="networkError"
  :message="networkError.message"
  @retry="refetchAll()"
/>
```

### 6.2 空班级检查

```typescript
// 开启课堂前检查
const handleStartSession = async () => {
  // 检查班级是否有学生
  const students = await getClassStudents(className.value)
  if (students.length === 0) {
    showErrorToast('该班级暂无学生，无法开启课堂')
    return
  }
  // ... 继续开启
}
```

## 7. 边界情况处理

| 场景 | 处理方式 |
|------|----------|
| 班级已被其他教师占用 | 下拉选项禁用，显示"已被XX老师占用" |
| 刷新时课堂被其他设备结束 | 静默更新，当前选中班级失效时自动切换到第一个 |
| 快速连续点击开始课堂 | 按钮loading状态，防止重复提交 |
| 结束课堂时网络断开 | 显示错误，不重置本地状态，允许重试 |
| 教师权限被撤销 | API返回403，跳转登录页 |

## 10. 风险评估

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 频繁轮询导致服务器压力 | 中 | 智能刷新策略，无课堂时30秒间隔 |
