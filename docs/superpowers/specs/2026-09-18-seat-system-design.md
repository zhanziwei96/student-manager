# 座位系统设计文档（座位图 + 入座签到）

---

**文档版本**: v1.0
**创建日期**: 2026-09-18
**状态**: 待用户审阅
**关联**: 现有课堂签到（course_sessions + checkin_records + 验证码）

---

## 1. 目标

每个学生在自己上课的教室有**固定座位**。学生登录网页后，在教室座位图上点自己的座位「坐下」，输入课堂验证码后完成签到——签到即人到。教师端可看到实时座位图（谁坐了/谁没到一目了然）。

## 2. 用户决策汇总（brainstorm 已确认）

| 决策项 | 结论 |
|---|---|
| 座位归属 | **座位属于教室**（学生在某教室上课的位置固定） |
| 座位图形态 | **桌子+椅子**的座位单元（参考网吧/自习室平面图），**简单网格**，不分区 |
| 座位编号 | **要座位编号**（如 `P20`），便于指认；坐下后显示姓名 |
| 座位个数 | **老师自己分配**（教师配置教室的座位布局：几排几列/座位数） |
| 座位分配 | **学生首次自选，之后固定**；教师可调整；**每学期可改** |
| 坐下与签到 | **坐下 = 签到**，但**仍需现有课堂验证码**验证通过才成功（防代签） |
| 视觉风格 | **深色科技风 + 网吧氛围**（深蓝黑底 + 霓虹发光 + 呼吸灯）——**仅座位图局部**，不动全局白色极简设计系统 |
| 入座人物 | **简笔画火柴人**（圆头 + 两点眼睛 + 微笑 + 简笔四肢，参考用户提供的小红书风格） |
| 入座动画 | 签到成功：火柴人**走来 → 搬开椅子 → 坐下**；签到失败（验证码错）：火柴人**挠头退回** |

## 3. 数据模型

现有 `course_sessions.classroom` 是**字符串**（如"机房302"），无独立教室表。座位系统需要教室成为独立实体以承载座位布局。

### 3.1 新增表

**`classrooms`（教室）**
| 字段 | 类型 | 说明 |
|---|---|---|
| id | int PK | — |
| name | str 唯一 | 教室名（如 机房302），与现有 `classroom` 字符串对应 |
| rows | int | 座位排数 |
| cols | int | 座位列数 |
| status | str | active/archived |

**`seats`（座位）**
| 字段 | 类型 | 说明 |
|---|---|---|
| id | int PK | — |
| classroom_id | int FK → classrooms | 所属教室 |
| seat_no | str | 座位编号（如 P20，教室生成规则：`P{排}{列}`） |
| row | int | 排（从讲台往后 1 起） |
| col | int | 列（从左往右 1 起） |
| 唯一约束 | (classroom_id, seat_no)、(classroom_id, row, col) | — |

**`seat_assignments`（座位分配，每学期一份）**
| 字段 | 类型 | 说明 |
|---|---|---|
| id | int PK | — |
| seat_id | int FK → seats | 座位 |
| student_id | str FK → students | 学生学号 |
| semester_id | int FK → semesters | 学期（每学期可重排） |
| 唯一约束 | (seat_id, semester_id) + (student_id, semester_id, seat 所属 classroom) | 一座一人/一人一教室一座 |

> 一个学生同一学期在不同教室可有不同座位（计算机课在机房302、理论课在教室201），故唯一约束含 classroom 维度。

### 3.2 现有表扩展

**`checkin_records`** 加 `seat_id: Optional[int] FK → seats`（记录这次签到坐了哪个座位，可空=旧数据/无座位签到）。

### 3.3 现有 `classroom` 字符串字段

`course_schedules.classroom` / `course_sessions.classroom` 保留字符串（显示用），但开课/排课时若填写的教室名在 `classrooms` 表中有匹配，则该课堂启用座位图。不强行 FK 化（教室字符串是历史遗留的宽松字段，本次只让"有座位图的教室"生效座位流程）。

## 4. 教室座位布局配置（老师分配座位个数）

- 教师/管理员在「教室管理」新建教室时配置 **排数 × 列数**，系统按 `rows × cols` 自动生成座位（编号 `P{row}{col}`）。
- 支持编辑布局（改行列数会重新生成座位；已有分配的座位若被删掉需提示）。
- 排课前看不到座位的教室（无 classrooms 记录）走原有纯验证码签到，不出现座位图。

## 5. 签到入座流程

```
学生登录 → 课堂签到页
  → 系统查当前活跃课堂（该班这节课）→ 课堂有教室且教室有座位图？
    ├─ 无座位图 → 走原有纯验证码签到（不变）
    └─ 有座位图 → 渲染座位图（深色网吧风）
        → 学生点座位：
            ├─ 首次（本学期此教室无分配）→ 点空位 → 输验证码
            └─ 已固定 → 我的座位高亮 → 点它 → 输验证码
        → 验证码校验（现有 verify_verification_code）
            ├─ 对 → 播放入座动画（走来→搬椅→坐下）→ 写 checkin_record(+seat_id) + seat_assignment（首次）→ 签到成功
            └─ 错 → 播放失败动画（挠头退回）→ 座位不占用 → 提示重输
```

## 6. 前端组件

| 组件 | 职责 |
|---|---|
| `SeatMap.vue` | 座位图渲染（网格、桌子+椅子座位单元、空/已占/我的三态、编号/姓名）、深色科技风、列间走廊 |
| `SeatUnit.vue` | 单个座位（桌面 + 椅子 🪑 + 编号/姓名） |
| `SeatCheckinAnimator.vue` | 火柴人 SVG 入座动画（走来→搬椅→坐下）与失败动画（挠头退回） |
| `StickFigure.vue` | 火柴人 SVG 组件（圆头/两点眼睛/微笑/简笔四肢，多姿势：走/站/坐/挠头/欢呼） |

座位图局部深色主题（`.seat-map-dark` 作用域 CSS），不影响全局白色极简。列与列之间留走廊空隙（grid 分组间距）。

## 7. 后端接口

| 接口 | 方法 | 说明 |
|---|---|---|
| `/api/v1/classrooms` | GET/POST/PUT | 教室 CRUD + 座位布局配置（rows×cols） |
| `/api/v1/classrooms/{id}/seats` | GET | 教室座位图（含本学期分配状态：空/已占姓名/是否我） |
| `/api/v1/seat-assignments/mine` | GET | 我的当前学期座位（按教室） |
| `/api/v1/checkin` | POST | 扩展：带 `seat_id`；校验该座位本课堂未被他人占 + 该教室本学期我未分配则占用 |

权限：教师看自己课堂的座位图实时状态；管理员/教师管教室与座位布局；学生只读座位图 + 坐自己座位。

## 8. 数据迁移

- 新建 `classrooms` / `seats` / `seat_assignments` 三表
- `checkin_records` 加 `seat_id` 可空列
- 无历史数据需回填（座位是新概念）
- 迁移幂等（参考 20260911c 的 `to_regclass` 守卫模式）

## 9. 测试方案

- 单元：座位生成（rows×cols → 编号）、座位分配唯一约束、坐下占座校验（同课堂同座位不可二人、一座一人）
- 集成：坐下签到全流程（首次自选固定、验证码错不占座、重复坐下幂等、教师看实时座位图）
- 前端：SeatMap 渲染三态、入座动画状态机（成功/失败分支）、验证码失败不占用座位

## 10. 范围之外（YAGNI）

- 不做分区（SVIP/学习区那种）——简单网格
- 不做座位预约/抢座——固定分配
- 不做换座申请审批流——教师直接调整
- 不动现有纯验证码签到（无座位图的教室不受影响）
- 不改全局设计系统（座位图局部深色）
