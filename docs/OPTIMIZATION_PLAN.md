#### 1.2 P0级别问题

**P0-1: ScoreLog重复记录问题**

- **位置**: `backend/app/crud/student.py:215-223` 和 `backend/app/events/handlers.py`
- **问题**: `update_student_score()`同时直接创建ScoreLog和发布事件，事件处理器又创建一条记录
- **修复方案**: 移除CRUD层的直接记录，完全依赖事件处理器

```python
# 当前问题代码
score_log = ScoreLog(...)  # CRUD层直接记录
session.add(score_log)
session.commit()
# 事件处理器又创建一条记录！
```

#### 3.2 P0级别问题

**P0-1: 学生登录仍使用旧版密码验证**

- **位置**: `api/routes/login.py:96`
- **代码**: `verify_password_hash(password, student.password_hash, student.salt)`
- **风险**: SEC-003修复不完整，学生密码验证存在兼容隐患
- **修复**: 使用新的`verify_password()`函数

```python
# 当前代码（有兼容性问题）
if not verify_password_hash(password, student.password_hash, student.salt):
    raise HTTPException(...)

# 建议修复
if not verify_password(password, student.password_hash):
    raise HTTPException(...)
```

**P0-2: 修改密码后未清除旧会话**

- **位置**: `api/routes/login.py:226-237`
- **风险**: 修改密码后旧设备仍可访问
- **修复方案**: 添加token_version机制，修改密码时递增

#### 3.3 性能瓶颈分析

| 问题 | 位置 | 影响 | 优化方案 |
|------|------|------|----------|
| N+1查询风险 | `students.py:62-66` | 列表构建效率低 | 使用列表推导式 |
| 学生列表获取 | `student.py:55-70` | 多次查询+Python去重 | 使用SQL的IN查询 |
| 审计日志同步写入 | `middleware.py:128-137` | 高并发瓶颈 | 异步队列或批量写入 |

**优化代码示例**:
```python
# 优化前 - 循环查询
students = []
for cls in assigned_classes:
    students.extend(get_students_by_class(session, cls))

# 优化后 - 使用IN查询
query = select(Student).where(Student.class_name.in_(assigned_classes))
students = session.exec(query).all()
```

## 风险与建议

### 高风险项

1. **SEC-003密码验证不完整**：影响所有学生用户登录安全
2. **会话失效机制缺失**：修改密码后安全隐患
3. **ScoreLog重复记录**：数据准确性问题

### 中风险项

1. **审计日志同步写入**：高并发性能瓶颈
2. **deps.py覆盖率低**：核心依赖缺乏测试
3. **API层直接操作Session**：架构分层破坏

### 建议

1. **优先修复P0问题**：安全相关 issues 立即处理
2. **建立性能基线**：添加压力测试，了解系统上限
3. **代码审查制度化**：PR必须包含测试，覆盖率不下降
4. **文档同步更新**：AGENTS.md随架构变化更新
