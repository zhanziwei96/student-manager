## 1. 文档概述

### 1.1 目的
本文档定义 ClassHub 班级管理系统的功能需求，涵盖当前已实现功能和未来版本规划。

### 1.2 范围
涵盖教学管理核心业务：学生管理、签到系统、分数管理、课程安排、考勤管理、作业任务、成绩评估、通知公告等。

### 1.3 术语定义

| 术语 | 定义 |
|------|------|
| 课程表 | 按周循环的排课计划 |
| 课堂会话 | 单次上课的签到时间段 |
| 平时成绩 | 由签到、作业、课堂表现组成的综合性评分 |
| 总评成绩 | 按权重计算的学期最终成绩 |
| 领域事件 | 系统中发生的业务事件，用于解耦模块 |
| 乐观锁 | 并发控制机制，防止数据竞争 |

## 2. 系统需求

### 2.1 功能需求 - 已实现

#### ✅ 学生管理 (已实现)
- 学生信息添加、删除、编辑
- Excel批量导入学生
- 学生密码重置
- 学生查询自己信息

#### ✅ 签到系统 (已实现)
- 网页签到（输入学号+姓名）
- 一机一签限制（IP+设备标识）
- 教师代签功能
- 实时签到状态显示
- 签到统计报表

- 乐观锁保护防止并发更新丢失（v3.0.0）

#### ✅ 用户认证 (已实现)
- JWT + HttpOnly Cookie认证

#### ✅ 课堂管理 (已实现)

#### ✅ 审计日志 (已实现)

### 2.2 功能需求 - 开发中/规划中

#### REQ-001: 多班级并行上课
**优先级**: 🔴 高  
**状态**: ✅ 已实现 (v3.0.0)  
**需求描述**: 支持同一时间段多个班级同时上课，互不干扰  
**业务场景**: 上午1-2节，2025级中药学1班、2班、3班同时在机房上课，各班级独立签到  

**功能要求**:
- 教师可同时开启多个班级的课堂会话
- 每个班级有独立的签到状态
- 学生按所属班级进行签到
- 教师可在不同班级间切换管理

**验收标准**:
- [x] 教师dashboard显示所有进行中的班级
- [x] 学生签到时自动匹配所属班级的进行中的课堂
- [x] 签到记录关联到具体班级和课堂会话
- [x] 统计报表按班级分别展示

---

#### REQ-002: 课程表/排课系统
**优先级**: 🔴 高  
**状态**: ✅ 已实现 (v3.0.0)  
**需求描述**: 建立课程表，支持按周课表自动/手动开启签到  
**业务场景**: 每周三3-4节是中药学4班的计算机应用基础课，系统自动允许该时段签到  

**功能要求**:
- 管理员/教师可创建周课表
- 课程信息：课程名、班级、教室、时间段、任课教师
- 支持单周/双周/每周/自定义周期
- 课程开始时间自动开启签到（可配置）
- 节假日/调课管理

**数据模型**:
```
Course: 课程基本信息
Schedule: 周课表（哪节课在哪个时间）
CourseSession: 单次上课实例（关联签到）
```

**验收标准**:
- [x] 可视化课表界面（教师视图）
- [x] 到上课时间自动推送"开始上课"提醒
- [x] 调课申请与审批流程
- [x] 课表导入导出（Excel）

---

#### REQ-003: 作业/任务管理
**优先级**: 🔴 高  
**状态**: 📋 规划中  
**需求描述**: 教师发布作业，学生提交，批改后自动关联成绩  
**业务场景**: 教师发布"Excel表格格式设置练习题"，学生提交文件，教师批改后+10分  

**功能要求**:
- 教师发布作业：标题、描述、截止时间、附件、分数
- 学生提交：文字、图片、文件（支持多格式）
- 教师批改：评分、评语、退回重做
- 成绩自动计入"平时成绩"维度
- 作业状态追踪：未提交/已提交/已批改

**验收标准**:
- [ ] 作业列表按课程/班级筛选
- [ ] 文件上传支持拖拽
- [ ] 截止前自动提醒未提交学生
- [ ] 批改界面支持批注（图片/PDF）

#### REQ-006: 成绩多维度管理
**优先级**: 🟡 中  
**状态**: 📋 规划中  
**需求描述**: 支持多种成绩类型，配置权重，自动计算总评  

**功能要求**:

**数据模型**:

**验收标准**:

## 3. 非功能需求

### 3.1 性能需求
- 课表页面加载时间 < 2秒
- 签到操作响应时间 < 500ms
- 报表导出支持500人班级 < 5秒
- 并发支持：100人同时签到

### 3.2 兼容性需求
- 支持 Chrome、Edge、Firefox、Safari 最新两版
- 移动端适配（学生主要用手机）
- 响应式设计：支持 320px - 1920px 屏幕

### 3.3 安全需求
- 密码加密：bcrypt算法（已实施）
- JWT认证：Token存储在HttpOnly Cookie
- 学生数据隔离（只能看自己的）
- 教师数据边界（只能管理负责班级）
- 操作日志记录（成绩修改、请假审批等敏感操作）
- 乐观锁保护：防止并发数据竞争（已实施）
- 限流保护：登录5次/分钟，签到10次/分钟（已实施）

### 3.4 可靠性需求
- 系统可用性：99.5%
- 数据备份：每日自动备份
- 故障恢复：RTO < 30分钟
